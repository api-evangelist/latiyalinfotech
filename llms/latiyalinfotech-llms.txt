## What is published

- Machine-readable contract: two first-party **Postman Collection v2.0.0** documents (51 and 30
  operations). There is **no OpenAPI, no GraphQL, no AsyncAPI, no MCP server and no agent card**.
- Base URL (direct): `https://apicricketchampion.in/apiv{3|4|5}/`
- Base URL (marketplace): `https://cricket-live-line4.p.rapidapi.com/`
- Auth (direct): opaque API token as the **final path segment** of every request.
- Auth (marketplace): `X-RapidAPI-Key` + `X-RapidAPI-Host` headers.
- Response envelope: `{"status": <bool>, "msg": <string>, "data": <array|object>}`.

## Things an agent must know before calling

- **HTTP status codes carry no application meaning.** An invalid credential returns **HTTP 200**
  with `status: false`. Branch on the `status` field, never on `response.ok`.
- **The version is the price tier.** `apiv3`, `apiv4` and `apiv5` are concurrently sold products
  with different operation sets; `teamList` and `playerList` are v5-only.
- **The API is read-only.** All 51 operations are reads. POST is used only to carry filter fields
  as `multipart/form-data`; nothing mutates provider-side state, so there is nothing to undo.
- **Consumption is cadence-governed, not header-governed.** No rate-limit headers are returned.
  The provider prescribes a polling cadence per operation: `liveMatch` every 700ms and
  `commentary` every second directly from the app; everything else on a server cron from once a
  minute to once a day, cached into the consumer's own database.
- There is no error code registry — failures are distinguishable only by English `msg` text.
